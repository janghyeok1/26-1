## proof by invariant
### recursive binary search
invariant: 어떤 i에 대해서 a[i]라면 위 함수는 i를 리턴
base: n = 0이라면, 'i는 a[i] = x'가 성립할 방법이 없고, 함수는 -1 리턴
step:
    case1: a[m] = x인 경우, m를 리턴 -> 성립
    case2: a[m] > x인 경우, a[m], a[m+1], ... , a[n-1] 중에서는 x와 같은 값이 없다. 따라서 a[i] = x인 경우가 있다면 i는 0 ~ m-1 사이에 존재한다. 함수는 재귀적으로 a[0] ~ a[m-1]에 대해 재탐색, base에 의해 이는 a[i] = x인 경우가 있으면 i를, 없으면 -1을 올바르게 리턴
    case3: a[m] < x인 경우
시간복잡도 O(log n) 
log(n): n를 2로 나눌 수 있는 횟수, n보다 월등히 작음
### selection sort
집합 조건을 꺨 수 있는 코드는 없음
invariant: k번째 루프가 끝난 후
    a[0] < a[1] < ... a[k-1]
    k-1보다 큰 모든 x에 대하여, a[x] > a[k-1]
base: k = 0, 둘다 null condition, true
step: k번째 루프가 끝났을 때, invariant가 성립을 증명, k+1번째 루프가 끝난 후
    a[k-1] < a[k]
    k보다 큰 모든 x에 대하여, a[x] > a[k]
## proof by induction
### recursive selection sort
sort(int a[], int n) -> sort(a+1, n-1)
집합 조건을 꺨 수 있는 코드는 없음
base: n=1, 할 일이 없음
step:
    n-1일 때, sort가 성공한다면 a[1] < a[2] < ... < a[n-1]
    -> n일 때, sort가 성공 a[0] < a[1] 성립
시간복잡도 O(n^2)
### recursive merge sort
merge algorithm: O(n)에 merge 가능
가장 작은 단위로 나누고, 왼쪽 sort, 이후 오른쪽 sort
집합 조건을 깰 수 있는 코드는 없음
base: n=1, 할 일이 없음
step:
    사이즈가 n/2일 때, sort 성공한다면 왼쪽은 정렬되어 있고, 오른쪽은 정렬되어 있음
    사이즈가 n일 때, 왼쪽과 오른쪽은 정렬됨
    (왼 1 + 1 merge -> 오 1 + 1 merge -> 왼 오 merge)
시간복잡도 O(n * log n)

## minimum spanning tree
### prim algorithm
아무데서나 시작, 기준 tree에서 인접한 edge 중 가장 작은 weight를 가진 edge 추가(사이클 만들지 않게), 반복
확실한 답을 모르는 상태에서, 더 나은 방법 찾기
정확성: 정답을 가정하고, 정답에 있는 edge를 넣으면 굿, 만약에 정답에 없는 edge를 넣는 상황에서 항상 모순을 찾을 수 있음.
정답이 무엇인지 구체적으로는 모름, 하지만 정답이 있다는 사실은 알고있다
이미 tree에 속한 노드를 따로 표시, edge를 추가할 때 tree에 속한 노드가 2개 있으면 사이클이 생긴다는 것을 알수있음 - priority queue 활용(이미 사이클이 생긴다고 판정되면 최후순위)
n 노드개수 m edge개수
시간 n + m log m(= n + m log n), 입력을 읽긴 해야하니깐 n + m보단 빠를수없음, sorting에 log m
모순:
    정답인 edge e'(가정한 정답)와 잘못 고른 edge e(알고리즘 중 추가할 답(가정과 다른 답))
    case1: if e > e', 가정한 정답 = 답이라는 것이 모순
    case2: if e < e', 가장 작은 weight를 추가한다는 알고리즘 내용과 모순
    case3: if e = e', 가정한 정답 이외에 다른 답이 존재(모순은 아님, 가정한 정답이 유일하지 않음)
### kruskal algorithm
가장 작은 weight부터 edge를 추가, cycle이 만들어지면 버림, 반복
시간 m log m(edge 정렬이 지배적, union find는 거의 상수 시간)
모순:
    정답인 edge e'(가정한 정답)와 잘못 고른 edge e(알고리즘 중 추가할 답(가정과 다른 답))
    case1: if e > e', 가정한 정답 = 답이라는 것이 모순
    case2: if e < e', 가장 작은 weight를 추가한다는 알고리즘 내용과 모순
    case3: if e = e', 가정한 정답 이외에 다른 답이 존재(모순은 아님, 가정한 정답이 유일하지 않음)
### prim and kruskal can find any solution

## shortest path
source to target, 두 node 사이 가장 짧은 길 찾기
### dijkstra algorithm
version: 길이만 찾는 알고리즘 -> 길이와 경로까지 찾는 알고리즘 -> 모든 답을 다 찾는 알고리즘
경로 중 어떤 지점을 새로 target으로 지정해도, 항상 shortest path -> target까지의 경로에 있는 모든 다른 노드까지의 shortest path까지 찾을 수 있음
weight가 음수인 edge가 존재하면 알고리즘이 정상적으로 돌아가지 않음

only length(undirected)
source는 정해져 있음, 모든 edge 중 제일 작은 것을 골라서 확정(greedy style)
다른 길을 선택하면 돌아서 가야 하기 때문에 확정된 edge보다 항상 김(가장짧아서 x, 다른 길로 갈려면 항상 더 길어서 o)
다음 파랑->빨강 선택은 빨간 애들만 거쳐서 가는 제일 짧은 길(파란애들을 거치지 않음)
최초는 항상 source에서 직접 가는 경로, 직접 경로가 없으면 inf
확정 후에는 방금 확정한 edge와 이어진 edge들을 업데이트(그외에는 최단 경로가 변하지 않음)
shortest path tree

prim vs dijstra
prim은 이미 확정된 애들하고 연결된 edge 중 가장 짧은 것을 선택(끝에것만 봄)
dijstra는 source에서부터의 거리가 가장 짧은 것을 선택(source와의 거리가 중요)
비슷해 보이지만, 완전히 다름

bellman-ford 다익스트라 전에 존재했던 shortest path, dijstra에서 '가장 짧은것부터' 찾는 부분을 뻄, edge에 음수가 있어도 돌아감(n번 돌려도 아직 edge가 남아있으면 음수 사이클이 있다고 판단)
