# process
process: 실행되고 있는 프로그램의 abstraction, 실행하는 중에만 존재
processor: 프로그램을 실행하는 하드웨어
program: 소스 코드 등 정적인 요소
context: process에 필요한 정보(program counter, register, main memory)
context switch

context를 동결하고 다른 process 실행, 여러 프로그램이 동시에 실행되는 것처럼 보임
다른 process를 실행할 때, OS의 scheduler가 먼저 실행되고 있던 process를 일시정지
switch할때마다 먼저 실행되고 있던 process의 정보를 save하고 다시 실행할 때 환원, 비용 발생
너무 드문드문하면 응답성이 떨어지고, 너무 자주하면 overhead
OS(kernel): process에 기생, process가 아니지만 process처럼 동작, timer interrupt에 의해 실행되어 switch
## virtual address space(main memory)
32bit 컴퓨터: 2^32개의 주소(byte단위)를 표현, 총 4GB(0xffffffff), 전부 사용하지는 않지만, 그렇다는 '착각'을 줌, 1GB 운영체제 + 3GB program

구성
kernel: OS가 차지하는 공간, context switch 등등
stack: 함수 호출에 사용, runtime에 동적으로 공간 차지, 아래로 성장
memory mappes region for shared libraries: 표준 라이브러리 등의 데이터
heap: malloc 할당 영역, 동적으로 공간 차지, 위로 성장
read/write data: global data, 전역변수, 정적
read only data: 코드 부분, 정적
unused: 주소 0, 미사용 공간
unused나 kernel로 접근시 exception error
## fork
1 call 2 return
기존 parent process와 새로 생긴 child process, 같은 코드에서 다른 분기로 실행, 실행 순서 모름
child 리턴값 0, parent 리턴값은 child의 pid
errno: system call에 error 발생시 사유 알려줌, 가장 마지막 error만 확인 가능, 0은 error 미발생
perror: error 발생시 시스템 오류 메시지 출력
EAGAIN: 프로세스가 너무 많아 더 이상 생성 불가(DDOS)
ENOMEM: 메모리 공간 부족
ENOSYS: 지원하지 않는 system call

man page
1: user command
2: system call
3: library function
## exit
return은 현재 함수 종료, exit는 해당 process 종료
atexit: exit 호출시 지정된 함수(인자 리턴 둘다 void) 호출
## zombie
종료되었지만 여전히 resource를 차지하고 있는 process
reaping: parent가 zombie child를 제거, child의 exit status 정보 가짐
명시적으로 reaping하지 않으면 init process(모든 process의 조상)가 처리
## wait
child 중 하나가 종료될 때까지 대기, 해당 child의 pid 반환
waitpid: 특정 process를 대상으로 wait, child와 parent의 종료 순서는 모르지만, 종료에 대한 등답 순서 조절
## exec
pid 등의 정보는 유지하면서 다른 process로 덮어씌움
인자 (경로, 이름, 인자, 인자, ..., 0)
인자를 하나씩 나열하면 execl, 문자열 배열로 전달하면 execv
실패하면 -1, 성공하면 반환 없음
# signal
event의 발생 여부를 알림, kernel -> process, 다른 프로세스의 요청으로 보내기도 함, ID와 도착 여부
도착했을 때 기본적으로 pending 보류, queuing되지 않음(중복 무시)
특정 signal을 block 가능
## send
pcb에 signal을 업데이트
kernel이 event를 자체적으로 발견한 경우(0으로 나누는 오류, child 종료), kill command 요청, system call로 kill 요청시 send
pcb: process control block, 구조체 형태로 존재, program counter, memory, register, signal 정보
## receive
ignore, process 종료, 사용자 지정 handler
pending: 각 bit마다 고유의 signal 번호가 matching되어 있음, signal 동시 전달 가능, 중복 표현 불가
blocked: block할 signal 표시
bit operator를 이용해 pending & ~blocked인 signal 판별
signal을 보낼 때, cpu는 발신자에게 배정되어 있기 때문에 수신자는 보류 상태, cpu가 수신사에게 배정된 이후 signal 확인

ctrl+c: sigint, 종료
ctrl+z: sigtstp, stop
sigstop은 stop, sigtstp은 user가 signal handler를 바꿀 수 있음

state
s: 입력 대기중
t: stop
r: 실행

## race condition

## simple shell eval function
명령을 parsing하여 argv와 bg 여부 결정
빈 줄이면 무시
내장 명령어가 아니면 fork로 자식 생성, 자식은 execv로 프로그램 실행(실패시 command not found 출력 후 종료), fg면 대기 후 reaping, bg면 pid와 명령어만 출력하고 다음 입력 대기
addjob: child를 job에 추가
deletejob: reaping한 child를 job에서 제거(reaping과 항상 함께 수행)
### problem1
fg는 제대로 대기하고 reaping, bg는 종료되면 zombie, 메모리 누수
solution: SIGCHLD handler에 while문으로 reaping
### problem2
invocation ordering issue: addjob보다 deletejob이 먼저 실행될 수 있음
modification ordering issue: linked list 포인터를 수정하는 도중 handler가 끼어들면 list가 깨질 수 있음
blocking in waitpid: child가 종료되지 않으면 shell 전체가 멈춤
idea: 공유 resource에 둘 이상의 thread 동시 접근을 막기, 실행 중이면 다른 thread가 들어가지 못하게 보장, 원자성(실행 중일 때 끼어들지 못하게 막기)
solution
implicit: kernel이 현재 처리 중인 signal과 같은 종류를 자동으로 차단
explicit: sigprocmask(SIGINT 차단)로 직접 제어, addjob과 deletejob 위아래로 sigprocmask(modification ordering issue), child기준 fork 위아래로 sigprocmask(invocation ordering issue)
result:
child: sigprocmask -> fork -> sigprocmask 해제 -> 정상 실행 -> 부모에게 SIGCHLD
parent: sigprocmask -> fork -> sigprocmask -> addjob -> sigprocmask 해제 -> SIGCHLD 수신 -> deletejob
blocking in waitpid: child 복수 존재, return한 child를 reaping한 후에도 아직 실행중인 child가 있으면 무한 대기
solution: handler에 WNOHANG 적용, 아직 실행 중인 child는 무시하고 parent 진행, 이후 child가 종료되면 reaping
### safe signal handling
handler는 메인 프로그램과 동시 실행, 전역 데이터를 공유, 손상 위험
G0: handler는 최대한 단순하게
G1: handler에서는 async-signal-safe 함수만 호출(signal에 의해 중단되지 않음)
G2: 진입시 errno를 저장하고 종료시 복원(메인 코드의 errno 덮어쓰기 방지)
G3: 공유 데이터 접근시 모든 signal을 일시 차단
G4: 전역 변수는 volatile로 선언(register에 캐싱하지 않고 항상 메모리에서 읽음)
G5: 전역 정수 플래그는 volatile sig_atomic_t로 선언(명령어 하나로 읽기/쓰기 보장)

while(!pid) pause: sigprocmask -> fork -> pid = 0 -> pid 체크 -> sigprocmask 해제 -> SIGCHLD 수신, pid 변경 -> pause
pid체크와 pause 사이에 child 종료시 다시 pid를 체크하기 전 SIGCHLD를 수신하여 pause에서 멈춤
while(!pid) sigsuspend: sigprocmask -> fork -> pid = 0 -> pid 체크 -> sigsuspend(sigprocmask 해제 + pause) -> SIGCHLD 수신, pid 변경 -> sigsuspend 해제, sigprocmask -> pid 체크 -> 루프 탈출 -> sigprocmask 해제

## processor state
temporary data: %rax 등등
%rsp: location of runtime stack
%rip: location of current code control point
CF, ZF, SF, OF: condition code, 최근 연산 결과
### condition code
1bit register, 산술 연산에서 부수적으로 자동 설정
CF: carry flag, 최상위 비트 자리올림
ZF: zero flag, a == b
SF: sign flag, 부호 존재하는 overflow(양수 overflow로 음수될때) 
OF: overflow flag, 부호 존재하는 overflow(양수+양수=양수, 음수+음수=양수, 양수-음수=음수, 음수-양수=양수)
leaq는 조건 코드를 설정하지 않음
## set
condition code 조합에 따라 dest의 하위 1바이트를 0(false) 또는 1(true)로 설정
sete: ZF, a == b
setne: ~ZF, a != b
sets: SF, 음수
setns: ~SF, 음수 아님
setg: ~(SF^OF) & ~ZF, a > b(부호 있음)
setge: ~(SF^OF), a >= b(부호 있음)
setl: SF^OF, a < b(부호 있음)
setle: (SF^OF) | ZF, a <= b(부호 있음)
seta: ~CF & ~ZF, a > b(부호 없음)
setb: CF, a < b(부호 없음)

# inter-process communication(IPC)
signal은 process 사이에 메시지를 보내는 아주 단순한 방법, 전달되는 정보가 signum밖에 없음
SysV IPC(UNIX 운영체제, SVR4가 가장 성공한 버전)와 POSIX IPC(IEEE 표준) 방식이 존재
## pipe
stream oriented, 구분 단위가 없음(1 + 10 send, 2 receive할때 1 + 1 receive)
first in first out, 단방향
가상의 device
### option
cat: concatenate and print, 한 번에 넘어감
more: 한 페이지씩 print
grep: 형식에 맞춰 print
sort: 정렬

cat f1 f2 | more: f1과 f2를 합쳐서 한 페이지씩 보기
cat f1 f2 | grep 'user jin' | sort > JIN: f1과 f2에서 username==jin에 해당하는 내용을 정렬하여 JIN이라는 이름의 파일에 입력
## message queue
message oriented, 특정 단위로 보냄(1 + 10 send, 2 receive할때 1 receive)
queue에 메시지 send/receice, 양방향, 물리적으로는 kernel이 linked list 형태로 들고 있음
SysV는 만든 queue가 없어지지 않음, POSIX는 unlink를 통해 제거
## shared memory
virtual memory shared between processes
기본적으로 어떤 process도 다른 process의 virtual memory에 접근 불가하지만, shared memory를 이용하여 가능
race condition 발생 위험
SysV POSIX 둘다 공간을 붙이고 뗄 수 있음
## semaphore
synchronization, shared memory에서 발생하는 race condition 방지
semaphore는 뮤텍스 대체 가능하지만 뮤텍스는 semaphore를 대체 불가
SysV POSIX 둘다 생략
## socket
endpoint of IPC flow across network, 컴퓨터 네트워크를 통해 process 간 통신(TCP/IP)
같은 node에 process가 존재하지 않아도 가능, 오히려 같은 node에서는 비효율적
OSI 7 layer중 4와 7 layer 사이에 존재
