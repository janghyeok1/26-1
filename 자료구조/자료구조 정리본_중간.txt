Linear Search
정렬되지 않은 배열에서, 인덱스 0부터 배열의 length만큼 값을 비교하며 탐색
시간복잡도: 0부터 배열의 length까지 비교하기 때문에 시간복잡도는 O(n)

Binary Search
정렬된 배열에서, 탐색할 배열의 중간 인덱스에 해당하는 값을 비교, 찾는 값이 크면 배열의 중간부터 끝,
찾는 값이 작으면 배열의 처음부터 중간까지를 다시 탐색할 배열로 지정하는 것을 받복
시간복잡도: 1회의 탐색마다 탐색 대상이 반절씩 줄어드므로 시간복잡도는 O(logn)

Selection Sort
정렬되지 않은 배열에서, 배열의 처음 값 a부터 시작하여 뒤의 값과 하나씩 비교해 가며 가장 작은 값을 저장,
가장 작은 값의 인덱스와 비교한 값 a의 인덱스의 값을 서로 바꿈, 이를 배열의 length - 1회만큼 반복
시간복잡도: 배열의 모든값에 대하여 뒤에 위치한 모든 값과 한번씩 비교를 하기 때문에 시간복잡도는 O(n^2)

Merge Algorithm
배열을 크기가 1이 될 때까지 '크기가 반인 2개의 배열'로 나누고, 이후 이 배열들의 값을 비교해 가며,
a[0]와 b[0]를 비교했을 때, a[0]가 작다면 a[0]를 새로운 배열에 추가, 이후 a[1]과 b[0]를 다음 차례로
비교하며 결국에 새로운 배열에 모든 값을 정렬하여 추가
시간복잡도: 하나의 배열을 크기가 1인 '원 배열의 length'개의 배열로 반씩 나누는 것을 반복하기 때문에
logn, 새로운 배열에 추가할 때 두 배열의 모든 값을 한번씩 비교하기 때문에 n, 시간복잡도는 O(n*logn)

1. 다음 재귀 함수의 시간복잡도를 구하고 그 이유를 설명하라.
cint func(int n) {
    if (n <= 1) return 1;
    return func(n/2) + func(n/2);
}
위 함수는 입력된 n의 값이 1 이하라면 1을, 그렇지 않다면 2를 나눈 몫의 값을 2배로 실행하는 함수이다. n = 2^k - @라고 한다면 1차 재귀는 호출 2회, 2차 재귀는 호출 4회, ... k회 재귀는 호출 2^k회이다. 총 호출횟수는 따라서 1+2+4...n이고
이 등비수열의 합은 2n-1이다. 따라서 함수의 시간복잡도는 O(n)이다.

2. Binary Search의 시간복잡도가 O(log n)임을 증명하라. 또한 정렬되지 않은 배열에서는 Binary Search를 사용할 수 없는 이유를 설명하라.
Binary Search는 정렬된 배열에서, 배열의 크기를 전체 탐색 범위로 지정하여 50%에 해당하는 값과 탐색하고자 하는 값을 x를 비교하고, x가 크다면 50%~100%를, 작다면 0%~50%에 해당하는 배열의 범위를 새로운 탐색 범위로 지정하고 또 그 안의 50%값을과 x를 비교하는
것을 반복하는 방식으로 탐색을 진행한다. 따라서 전체 배열의 크기 n = 2^k - @라고 한다면, 탐색은 K회 진행하기 때문에 전체 시간복잡도는 O(logn)이다.
Binary Search는 값의 크기 순으로 배열되었다는 전제조건 하에 탐색이 진행되기 때문에, 만약 정렬되지 않은 배열에서 사용한다면 처음 50%에 해당하는 범위보다 x가 크다고 가정해도, 다음 범위인 50% ~ 100% 범위 사이에 x가 존재하지 않을 수 있기 때문에 x와 일치
하는 배열의 값이 있음에도 불구하고 탐색이 실패할 수 있다. 

3. Merge Algorithm의 시간복잡도가 O(n log n)임을 나누는 단계와 병합하는 단계로 분리하여 증명하라.
Merge Algoritm은 크게 크기가 n인 배열을 크기가 1인 n개의 배열로 나누는 단계와, 이 배열의 인덱스를 이용해 하나의 배열로 병합하는 단계의 2단계로 이루어져 있다.
나누는 단계에서는, Binary Search와 비슷한 방식으로, 배열의 크기가 1보다 크다면 배열을 크기가 반절(이때, 정확히 반절이 아닐 수 있음 예로, 크기 5의 배열은 /2를 하면 2가 되기 때문에 크기가 2와 3일 배열로 나눔)인 2개의 배열로 나누는 것을 반복한다.
이때 배열의 크기 n = 2 ^ k - @라고 한다면 배열을 나누는 루프의 횟수는 k회이기 때문에 재귀의 깊이가 log n이 된다.
병합하는 단계에서는, 두 배열의 인덱스 0부터 시작해서 마지막 값까지 하나씩 비교해 가며 새로운 배열에 추가하고, 또 이 새로운 배열들을 같은 방식으로 비교해 가며 새로운 배열에 추가하는 방식을 반복하기 때문에 각 단계마다 n개의 수를 비교하여 대입한다.
(예를들어, 크기가 8이라면 가장 아래 단계에서는 크기가 1인 배열을 8회, 그 위 단계에서는 크기가 2인 배열을 4회, ... 마지막 단계에서는 크기가 4인 배열을 2회 비교) 따라서 이떄의 시간복잡도는 O(n)이라고 할 수 있다.
Merge Algorithm은 이 나누는 단계와 병합하는 단계를 합쳐서 실행하기 때문에 O(n*logn)이 알고리즘의 시간복잡도로 나온다.

5. Text에 Pattern P로 string matching을 한 결과가 주어져 있다. 이번에는 Text에서 Pattern P가 연속으로 2번 이상 겹치지 않고 등장하는 모든 위치를 찾는 O(n) 알고리즘을 제시하라. (기출 문제의 변형: K번 이어붙이기가 아니라 "겹치지 않는 연속 2회 등장")
Text와 원소의 개수가 같은 int형 배열 b를 새로 정의한다(0으로 초기화). Text의 인덱스 0부터 시작하여, 각 string matching에 성공한 첫 번째 인덱스를 찾고, 해당 인덱스에서 P의 길이(원소의 개수)의 값을 뺀 만큼의 인덱스에 해당하는 값(이 인덱스가
0보다 작은지 확인해서 작다면 1을 대입하는 경우와 동일하게 처리)이 1 이상이라면, 해당 인덱스에 2를 대입하고, 0이라면 1을 대입하는 함수를 정의한다. 이 함수가 끝나면 숫자가 2인 모든 인덱스에서 P의 길이의 값을 뺀 만큼의 모든 인덱스가 p가 연속으로 2번 이상 겹치지 않고 등장하는 모든 위치이다.
이 알고리즘은 b의 길이(=Text[]의 길이)만큼 비교를 진행하고, 이후 b의 값이 2인지 체크하는 비교를 1회 진행하기 때문에 시간복잡도는 O(n)(n+n)이다.

6. packed sorted 배열과 sorted linked list에 대해 Search, Insert, Delete 연산의 시간복잡도를 각각 구하고 표로 비교하라. 또한 각각의 자료구조가 더 유리한 상황을 구체적인 예시와 함께 설명하라.
packed sorted 배열
Search: O(log n), 이진 탐색
Insert: S + O(n), 삽입 후 뒤에 있는 원소를 밀어냄
Delete: S + O(n), 제거 후 뒤에 있는 원소를 당김
sorted linked list
Search: O(n), 연결리스트는 head노드부터 시작하여 해당 노드의 포인터가 가리키는 노드로밖에 갈 수 없기 때문에 선형 탐색과 비슷한 방식으로 수행
Insert: S + O(1), 삽입할노드 n, 그 전후를 a, b라고 한다면, 탐색에 성공한 시점에서 a의 포인터를 n을, n의 포인터를 b를 가리키게 Insert를 수행하기 떄문에 O(1+1) = O(1)
Delete: S + O(1), 같은 방식으로 삭제할 노드를 n이라고 한다면 a의 포인터를 b를 가리키게 함으로써 Delete를 수행하기 때문에 O(1)
배열의 경우에는 탐색이 좋고, 삽입과 제거가 나쁘기 때문에 Insert와 Delete를 수행할 필요가 거의 없는 상황(ex 법률이나 책)에서 사용하기 유리하고
Linked List의 경우에는 탐색은 나쁘지만 Insert와 Delete가 좋기 때문에 자료를 자주 수정하는 경우(ex 작업 대기열, 플레이리스트)에서 사용하기 유리함.

7. DFS를 이용한 Equivalence Relation 판별에서, n개의 노드와 e개의 edge가 있을 때
(a) 인접 행렬 방식의 시간복잡도를 구하고 그 이유를 설명하라.
(b) 인접 리스트 방식의 시간복잡도를 구하고 그 이유를 설명하라.
(c) e가 어느 정도일 때 두 방식의 시간복잡도가 같아지는지 답하라.
(a) 인접 행렬 방식은 먼저 노드의 개수인 n * n의 행렬을 만들어 edge가 있는 모든 관계에 대해 true, 없는 위치에는 false를 부여하고(이동 위치의 로그 DFS를 기록할 배열을 하나 정의), 특정(보통 첫번째) 노드에서 시작해서 하나씩 비교해 가며 
true인 노드가 있다면 해당 이동, 없다면 다시 이전 노드로 돌아와서 다시 비교를 하는 방식으로 진행한다. 전체 시간 복잡도는 n*n의 행렬을 모두 돌기 때문에 O(n^2)이다.
(b) 인접 리스트 방식은 n개의 노드에 대해 edge가 있는 모든 노드만 기록해 두고, 선형 탐색과 비슷한 방식으로 각 노드마다 하나씩 비교를 수행하며 탐색을 진행한다. 이는 모든 노드에 대해 2e만큼의 비교가 이루어지기 때문에 시간복잡도 O(n + e)이다.
(c) 각각의 노드가 다른 모든 노드에 edge가 있는 경우에 두 방식이 같아진다.

9. Doubly Linked List에서 Dummy Node(head dummy, tail dummy)를 사용할 때의 장점을 Insert와 Delete 연산 관점에서 구체적으로 설명하라. 특히 "경계 조건(boundary condition)에서 NULL 체크가 사라지는" 이유를 예시로 들어라.
일반적인 doubly linked list는 head와 tail 노드에 대해 각각 포인터가 NULL인 경우가 존재한다. 만약 Dummy node를 활용한다면 NULL인 경우를 처리하지 않아도 되기 때문에(더미를 제외한 헤드에서는 이전 노드 포인터에 음의 무한대, 테일에서는 그 반대)
조건문 추가 없이(필요 없느 분기가 나눠지지 않음) 무조건적으로 모든 노드에서 Insert를 수행할 때는 (추가 또는 제거할 노드 n 그사이 a b), a의 다음 노드 포인터를 n, n의 이전 a, 다음 b, b의 이전 n으로 대입, Delete를 수행할 때는 a의 다음노드
포인터를 b, b의 다음노드 a로 대입하는 것으로 작업이 종료되어 코드가 단순해지고 버그의 가능성이 적어지고 성능 또한 아주 조금이지만 좋아진다.
