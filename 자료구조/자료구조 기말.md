# skip list idea from linked list
    linked list와 비슷하게 다음 원소를 가리키는 포인터 존재
    S1: -inf           6       +inf
    S2: -inf     2     6     9 +inf
    S3: -inf 1 2 3 4 5 6 7 8 9 +inf
## search(탐색 위치, key s)
    기존 시간 O(n) 공간 O(n)
    메모리를 n/2, n/2 + n/4...만큼 추가하여 시간 n/2, n/4..., 최종 search O(log n)
    가장 위 레벨 가장 왼쪽에서 시작, 오른쪽으로 이동
    오른쪽 노드 key가 s보다 크면 down
    가장 아래 레벨까지 반복, 해당 레벨에서는 탐색 == s면 탐색성공
## insert(삽입 위치, key i)
    search로 삽입 위치 찾기(i)
    i기준 좌우 가장 가까운 up이 존재하는 노드 p q 탐색
    p와 q 사이 노드 수가 0, 1, 2개면 i 삽입 후 종료
    p와 q 사이 노드 수가 3개면 2번째 노드를 상위 레벨로 승격(4개 경우 존재 x)
# binary search tree(BST)
    각 node는 key 존재
    반드시 하나의 root 존재(else 빈 트리), root는 1 or 2개 child 가짐
    각 child를 root로 하는 sub tree(BST 성립) 존재
    항상 left child < root < right child
## search(탐색 위치, key)
    search(노드, key)
    (key == 노드) 반환
    (key < 노드) search(left child, key)
    (key > 노드) search(right child, key)
    worst case: O(height), 편향된 트리 height = n
## insert
    search 실패 위치에 insert
    +inf가 항상 root 위에 dummy로 존재, 실제 root도 dummy의 left child에 위치, root를 교체(빈 트리에 insert)하는 special case 무시
    random insert 시, 첫 insert값이 root, 평균적으로 높이는 O(log n)
    worst: 편향, O(n)
    average, best: O(log n)
## delete
    search 성공 위치에 delete
    case 1: no child: 그냥 delete하고 종료
    case 2(1 child): delete 위치에 자식을 올림(linked list delete와 유사)
    case 3(2 child): d의 right subtree 중 가장 작은 값 x(가장 왼쪽)를 d위치에 올리고 x를 delete
# AVL tree
    BST 확장, 각 노드에 left, right subtree 높이를 나타내는 값 L R 존재
    L R의 차는 항상 0 또는 1, BST의 worst case를 방지
    노드가 많아도 항상 높이, search O(log n) 보장
## insert(삽입 위치, 값 i)
        a   
     b     c
    d e      
    case LL(left child의 left subtree로 삽입): b는 root, a는 root의 right child, e는 a의 left child(오른쪽 회전)
    case RR과 유사
         a    |     b
      b     c |  d     a
     d e      | i     e c
    i
    case LR(left child의 right subtree로 삽입):
    1. e는 root, b는 root의 left child, a는 root의 right child(왼쪽 회전)
    2. e는 root, a는 root의 right child
    case RL과 유사
        a    |     a     |   e
     b     c |  e     c  | b   a
    d e      | b i       |d   i c
       i     |d          |
# 2-3 tree
    각 node는 key 2개, child 3개까지 저장할 수 있음
## insert
    case 1(leaf already has 0 or 1 key): 그냥 insert하고 종료
    case 2(leaf already has 2 key): insert 후 key를 각 node로 split, 중간 key를 부모로 올림
    case 2.1(parent already has 1 key): 그냥 insert하고 종료
    case 2.2(parent already has 2 key): split, 이후 반복
    case 2.3(no parent): 새 parent root 생성
    bottom-up 방식(insert 후 split)
# 2-3-4 tree
    각 node는 key 3개, child, 4개까지 저장할 수 있음
    확장 -> B tree / B+ tree
## insert
    case 1(leaf already has 0 or 1 or 2 key): 그냥 insert하고 종료
    case 2(search 중 3-key node 조우시): split 후 중간 key 부모, 이후 insert
    top-down 방식(split 후 insert)
## 2-3 vs 2-3-4
    2-3은 탐색 후 leaf에서 split -> parent로 올라가서 또 split... 반복(비효율적)
    2-3-4는 탐색 중 모든 3-key를 미리 split, parent로 올라갈 일이 없음
# red-black tree
    2-3-4 tree를 이진 트리로 표현, black(일반BST), red(2-3-4노드 안의 연결)
    default: black node
    1 child: red link
    2 child: both black link
    1 child that has 2 child: red link
    2 child that has 2 child: both black link
    red link 연속 불가, 모든 경로의 black link 수 동일, 회전 없음
## insert
    bottom-up: red link로 insert 후 연속 red 생기면 회전(AVL의 case 판정과 동일)
    top-down: 내려가면서 node that has 2 red link 만나면 해당 node와 자식의 link 반전
## 2-3-4 tree & red-blck tree match
    node 내부 연결: red
    node 간 연결: black
## red-black vs AVL
    공통점: 최장경로 <= 최단경로 * 2(높이 O(log n))
    AVL: 좌우 높이 차 최대 1(엄격)
    red-black: 좌우 높이 차 최대 2배(느슨) -> 회전이 적어 상대적으로 유리
# splay tree
    자주 접근하는 노드가 root 근처로 이동(splay)
    최악 O(n), 평균 O(log n)
    n번 insert 포함 m번 연산 -> O(m log n)
## splay
    모든 연산의 기반, key(또는 가장 가까운 값, left subtree의 max값으로 지정)를 root로 올림
    case ZIG(key가 root의 child): key 회전
    case ZIG-ZIG(key와 parent 같은 방향): 부모 회전 후 key 회전, 단순 key회전 2회 반복시 편향 유지
    case ZIG-ZAG(key와 parent 반대 방향): key 회전 2회(반대방향)
## search
    splay(key) 후 root == key면 탐색 성공
## insert
    splay(key)
    root 기준 left right subtree L R 분리
    key를 root, L R를 각각 root의 subtree로 연결
## delete
    splay(key)
    root delete, left subtree max값을 root로 이동, L R을 다시 root에 연결
# priority queue
    first in 우선순위 out
    배열로 구현시 insert or delete 중 하나 반드시 O(n)
    AVL, 2-3, 2-3-4, red-black 구현시 insert, delete 모두 O(log n)이지만 더 효율적인 구현 존재
# heap
    조건: 마지막 레벨 제외 full, 마지막 레벨은 왼쪽부터 채움
    parent < child, parent는 항상 min, left right child 간의 비교 없음
    배열로 표현(root는 인덱스 1, left child는 parent*2, right child는 parent*2 + 1)
## insert
    1. 배열 마지막에 삽입
    2. parent(인덱스 key/2)와 비교하여 작으면 swap, 크면 종료
    3. 종료시까지 반복
    O(log n)
## delete
    1. root 제거(인덱스 1)
    2. 마지막 노드를 root로 이동
    3. min(left child, right child)와 비교하여 크면 swap, 작으면 종료
    4. 종료시까지 반복
    O(log n)
## heap sort
    1. 배열을 max heap으로 변환
    2. root를 맨 뒤와 swap(1개씩 정렬완)
    3. 다시 root만 max heap으로 변환 반복(n-1회)
    마지막 인덱스부터 정렬완, 결과적으로는 정렬된 배열
    O(max heap + n * log n)
### max heap
    child가 존재하는 모든 node를 인덱스기준 내림차순으로 child와 비교하여 작으면 swap, 크면 종료 다음 node 확인 or 종료, swap이후 child 존재하면 한번 더 비교
    O(n)
# dijkstra algorithm
    처음 노드 S에서 다른 모든 노드까지의 최단 경로 탐색
    red는 확정된 최단 경로(거리 0), blue는 임시 경로
    음수 거리 존재 불가능
## algorithm
    initial: S 거리 0(red), S와 직접 연결된 노드의 거리 blue 저장
    1. blue 중 최단 거리 노드 선택 후 red, 해당 노드에서 직접 연결된 노드의 거리 blue 저장(직접 연결 없으면 inf)
    2. S와 직접 연결된 노드 + red를 거치는 노드 중 최단 거리 노드 선택 후 red, 해당 과정 반복
    3. 모든 노드가 red로 연결
## performance
    without heap: (blue 전부 순회 n * 노드 수 n) + blue 재계산 m, O(n^2 + m)
    with heap: (최소값 root delete log n * 노드 수 n) + (heap 재정렬(log n) * blue 재계산 m), O({n + m} * log n)
    연결이 적으면(m < n^2) with heap 유리, 연결이 많으면(m == n^2) without heap 유리
# parsing algorithm
    수식을 inorder로 tree 변환, compile과정에서 중요
    S1에 연산자, S2에 피연산자 저장, 수식 앞뒤에 우선순위 최저 $ 추가
    우선순위: ( > * / > + - > ) > $
    () 만나면 괄호, $$ 만나면 종료
## idea - tree traversal
    모든 노드를 특정 순서대로 visit(단순 방문 X, 노드에서 어떠한 작업을 수행)
          a
       b     c
      d e   f g 
    preorder(root - left - right): 왼쪽 끝까지 내려감, 이후 하나씩 올라와서 오른쪽 방문, 항상 root가 첫번째, a b d e c f g
    inorder(left - root - right): 왼쪽 끝까지 내려가서 방문, 이후 parent, right 순서대로 방문, BST에서 수행하면 정렬된 순서, d b e a f c g
    postorder(left - right - root): 왼쪽 끝까지 내려가서 방문, 이후 right 방문하고 parent, 항상 root가 마지막, d e b f g c a
    수식을 포함한 계산에서, postorder방식이 코드 생성에 중요(연산자를 만났을 때, 앞의 두 피연산자가 이미 계산된 상태)
## input
    $ (A / B + C) * (A - D) + C $
    1. $ push to S1
    2. ( push to S1
    3. A push to S2
    4. / push to S1
    5. B push to S2
    6. +, T1(A / B) push to S2, + push to S1
    7. C push to S2
    8. ), T2(T1 + C) with () push to S2
    9. * push to S1
    10. ( push to S1
    11. A push to S2
    12. - push to S1
    13. D push to S2
    14. ), T3(A - D) with () push to S2
    15. +, T4(T2 * T3) push to S2
    16. C push to S2
    17. $, T5(T4 + C) push to S2, fin
## code generation
    완성된 parse tree를 postorder로 visit, 연산자 방문시 피연산자를 이용해 계산하여 임시변수 할당
    연산자를 만날때마다 항상 피연산자는 2개, 준비된 상태
# kruskal algorithm
    minimum spanning tree: 그래프에서 모든 노드를 연결하는 간선 합이 최소인 부분 그래프
    1. 간선 오름차순 정렬
    2. 가중치 작은 간선부터 추가, 사이클생기면 skip
    3. n-1개 간선 추가 시 종료
    DFS 사이클 판별은 그래프 전체 탐색 필요(노드 수 n * 간선 수 m), 비효율적
## union find(disjoint set)
    initial: 노드 n개, 각자 본인이 root인 n개 그룹, 각 노드는 parent pointer 저장
    union(a, b): b를 a의 child
    find(a): a의 root, find(a) == find(b)면 같은 그룹(사이클 형성)
    worst case: 편향된 트리, 부모 포인터를 계속해서 올라가야함
## optimize
    idea 1.1 union by size: 노드 수가 적은쪽을 child(별도 배열 필요)
    idea 1.2 union by height: 높이가 작은쪽이 child(별도 배열 필요)
    트리 높이, find O(log n) 보장
    idea 2 path compression: find할 때 거치는 모든 노드의 parent pointer에 root 저장
    O(log(log...)), 아무리 큰 수도 4 이하, 결과적으로 O(1)
## performance
    간선 정렬: m개 간선을 일반적인 방식으로 정렬, O(m * log m)
    union find: m개 간선 모두 find(), O(m * 1)
    result: 간선 정렬 + union find, O(n * log n)
# hash table
    hash function: 문자열 key를 정수로 변환해 배열 인덱스로 사용
    λ = 전체 key 개수 / table size, 테이블이 찬 정도
    collision: 삽입할 인덱스에 이미 값이 존재하는 경우 재탐색
    best case: search O(1), 편향되지 않음, collision 최소화, 메모리 낭비 적음
## hash function
    hash(x): 정수(x) % table size
    hash2: 소수 - (정수(x) % 소수), 간격
    table size는 소수인 경우가 좋음, else 메모리 낭비 경우 존재
    Horner's rule: 문자열 2자 이상인 경우 정수(x) = x[1] + x[2] << 5 ...
## separate chaining
    collision 해결의 한 방법, 각 인덱스를 linked list로 유지하여, 같은 인덱스에 여러 값 저장
    search: 실패시 O(λ), 성공시 λ/2 + 1
    best case: λ = 1, search O(1)
## closed hashing
    한 인덱스에 하나의 값, collision 발생 시 다음 위치 탐색
    linear probing: 인덱스 + 1,2,3, cluster(값이 존재하는 인덱스가 모여 있어 탐색 비용 증가) 형성
    quadratic probing: 인덱스 + 1,4,9, 인덱스가 table size/2를 넘어가면 이미 방문한 인덱스 재방문 -> λ 0.5이하여야 함
    double hashing: hash + hash2 * 1,2,3, 가장 균등
    lazy deletion: 그냥 삭제할 경우 탐색 경로 끊김, 인덱스는 남기고 값을 #로 처리해 (값이 없으니 그냥 넘겨라) 표시
### rehashing
    table이 가득 차면 크기가 2배인 새 table을 만들어 전체 재삽입
    시간: O(1), n이지만 전체 삽입 기준 log n회 수행
    overflow buckets: collision 발생시 별도 공간에 저장
    dynamic hashing: 인덱스가 차 있으면 해당 부분만 쪼갬, 나머지 table은 rehashing 없이 점진적으로 확장
    bloom filter: 탐색 실패가 많을 경우, table 접근 전 bitmap(mark 표시와 유사)으로 값 존재 여부 먼저 확인(0 하나라도 있으면 확실하게 없음)
# graph
    vertex(node)와 edge(간선)로 구성
    simple graph: 방향 없음, self-loop 없음, 중복 간선 없음
    multigraph: 동일 두 vertex 사이 여러 간선 허용
    pseudograph: self-loop 허용
    digraph: 방향 있는 그래프
## degree
    undirected: 해당 vertex에 연결된 간선 수(self-loop는 2로 계산)
    directed: in-degree(들어오는 간선), out-degree(나가는 간선)
    handshaking theorem: 모든 vertex degree 합 = 2 * (각 vertex에 연결된 edge 합), 홀수 degree vertex 수는 항상 짝수
## graph patterns
    완전 그래프 Kn: n개 vertex 모두 연결
    사이클 Cn: n각형
    휠 Wn: Cn + 중앙 vertex
    n-cube Qn: 이전 graph를 복사하여 연결
    bipartite: vertex를 두 그룹으로 나눠 같은 그룹끼리 간선 없음, Cn은 n이 짝수일 때만 bipartite
## adjacency matrix
    n x n 행렬, [i][j] = i->j 간선 수
    undirected는 대칭 행렬
## graph isomorphism
    두 그래프가 vertex 재배치로 동일해지면 isomorphic
    조건: vertex 수, edge 수, degree 분포 동일 필요(충분 조건은 아님)
    비동형 증명: 위 조건 하나라도 다르면 비동형
## paths
    path: 간선의 연속 sequence로 vertex 이동
    simple path: 중복 간선 없음
    circuit: 시작과 끝 vertex 동일한 path
## connectivity
    connected: 모든 vertex 쌍 사이 path 존재
    connected component: 서로 연결된 최대 vertex 집합
    N-connectivity: N개 vertex 제거해야 disconnected → 네트워크 견고성
    directed: weakly(undirected로 보면 연결), semi(일방통행 가능), strongly(양방향 모두 가능)
# web search ranking
    문서 집합 D와 query q에 대해 각 문서의 관련도 score s(d) 계산
    전통 모델: TF-IDF (문서 내 빈도 / 전체 빈도), 문서를 신뢰한다는 가정
    웹은 다름: 사람들이 거짓 정보 게시, 상업적 목적, 무관 정보 범람
## HITS model
    hub score: authority 높은 문서를 많이 가리킬수록 높음
    authority score: hub 높은 문서에 많이 가리켜질수록 높음
    상호 재귀적으로 수렴할 때까지 반복
## pagerank
    random surfer 모델: 링크를 따라가거나 랜덤 문서로 이동할 확률
    PR(pi) = (1-d)/N + d * Σ PR(pj)/L(pj), d=damping factor
## katz status

Q4. 2-3 tree와 2-3-4 tree의 insert 방식(bottom-up vs top-down)을 비교하고, 2-3-4 tree가 더 효율적인 이유를 설명하라.
2-3 tree는 insert 이후 해당 node에 값이 3개라면 split(중간위치 값을 올리고 나머지 두 값을 각각 자식 노드로 나눔)하고, 올라간 값에서 한 번 더 값 개수를 체크하기 때문에, insert를 위한 내려가는 과정 1회, split을 위한 올라가는 과정 1회의 시간이 소요된다.
2-3-4 tree는 insert를 위한 값 비교 중 값이 3개라면 split을 수행하며 내려가기 때문에 insert를 위한 내려가는 과정 1회의 시간만이 소요된다. 
(split하는 시간은 두 tree 모두 동일하기 때문에 계산에서 제외)

Q6. 다음 배열을 max heap으로 변환하는 과정을 단계별로 보여라: [-, 3, 1, 4, 1, 5, 9, 2, 6] (인덱스 0 미사용)
이후 heap sort의 전체 시간복잡도를 도출하라.
인덱스가 8까지 존재하기 때문에, 인덱스 4, 3, 2, 1 순서대로 child와 값을 비교하여 더 큰 child가 부모보다 크다면 swap
인덱스4(1) child 6 -> 6과 swap
인덱스3(4) child 9,2 -> 9와 swap
인덱스2(1) child 6, 5 -> 6과 swap -> 인덱스4(1) child 1, -> swap 안함
인덱스1(3) child 6, 9 -> 9와 swap -> 인덱스3(3) child 4, 2 -> 4와 swap
heap sort는 max heap에서 root(인덱스1)를 배열 마지막(인덱스 마지막)과 swap하고 root에서 max heap을 수행하는 과정을 노드개수-1만큼 반복하기 때문에 전체 시간 복잡도는 n(처음 max heap) + n(반복) * log n(root에서 max heap), 정리하면 O(n * log n)이다.

1. Skip list에서 search 연산의 시간복잡도가 O(log n)이 되는 이유를 설명하라.
skip list는의 search는 binary search와 비슷하게 매 레벨마다 탐색 범위가 약 1/2로 줄어들기 때문에 n개의 자료 중 log2 n개의 자료(각 레벨의 비교 횟수 합)만 비교를 수행한다.

2. BST에서 delete 연산의 case 3(2 child인 경우) 처리 방법을 설명하고, 그 이유를 서술하라.
delete한 값의 바로 앞 index 또는 바로 뒤 index에 위치한 값을 delete한 위치로 이동한다. 이렇게 수행하면 이동을 수행한 node 기준 left subtree는 node보다 작고, right는 node보다 크기 때문에 BST가 성립한다.(left subtree의 가장 오른쪽에 있는 값은 나머지 left subtree의 모든 값보다 크고, right의 경우 동일)

3. AVL tree의 LR case에서 발생하는 회전 과정을 그림과 함께 설명하라.
LR case는 root의 left child의 right subtree에서 insert가 발생한다. 따라서 avl tree를 맞추기 위해서는 insert하는 node가 포함된 subtree 기준 left로 1회 회전 이후, root 기준 right로 1회 회전한다.

4. 2-3 tree와 2-3-4 tree의 insert 방식(bottom-up vs top-down)을 비교하고, 2-3-4 tree가 더 효율적인 이유를 설명하라.
2-3 tree는 새로운 insert 수행 시, search로 삽입 위치 탐색, insert, 해당 노드의 값 개수 판정, split, parent node에서도 판정, split의 과정을 최대 root까지 올라가며 수행, 2-3-4 tree의 경우에는 root에서 시작하여 개수 판정, split, child 판정 split... 이후 search가 끝나면 바로 삽입하고 끝나는 방식이다. 2-3-4 tree는 2-3트리의 올라가는 과정이 없기 때문에 더 효율적이다

5. Red-Black tree와 AVL tree의 균형 조건을 비교하고, Red-Black tree가 회전이 더 적은 이유를 설명하라.
red-black tree는 회전의 조건이 red가 연속 등장 or red를 2개 가진 node, avl tree는 root에 저장된 left height와 right height의 차가 2일때이다. 따라서 red-black tree는 black 수 vs black 수 + red 수(최대 black - 1)인 최대 2배 height, avl tree는 최대 1 차이까지 회전을 수행하지 않기 때문에 조건이 더 널널하다.

6. Splay tree에서 ZIG-ZIG case에 단순 회전을 2회 반복하지 않고 별도의 회전 방식을 사용하는 이유를 설명하라.
zig-zig case는 avl tree의 LL, RR case와 유사한, root 기준 child 방향과 search할 node의 parent 기준 search할 node의 방향이 같은 경우를 말한다. 이 경우에 같은 노드 기준 단순 회전을 2회 반복한다면 tree의 편향이 해소되지 않고 chain 형태가 새 root 근처에 남게 된다. 따라서 parent를 먼저 회전하여 parent 기준 균형을 맞추고, 본인을 회전하여 전체 tree의 불균형을 그나마 해소할 수 있다.

7. 배열을 이용한 heap에서 부모와 자식 노드의 인덱스 관계를 설명하고, insert 연산의 과정을 O(log n)이 되는 이유와 함께 서술하라.
부모는 항상 자식의 /2(나머지 버림), 자식은 항상 부모의 *2(left) or *2+1(right)인덱스를 가진다(인덱스 0에는 값이 없음). heap 구조는 모든 경우에서 편향되어 있지 않고, 높이가 항상 log n이기 때문에 insert 시간 복잡도는 높이(=탐색횟수)인 log n이 된다.

8. Dijkstra 알고리즘에서 heap을 사용했을 때와 사용하지 않았을 때의 시간복잡도를 각각 구하고, 어떤 경우에 어느 방법이 유리한지 설명하라.
heap 미사용: blue 갱신 + 노드를 탐색하여 blue 탐색 * 노드 수 = m+n^2

10. Kruskal 알고리즘에서 union by size/height와 path compression을 함께 적용했을 때, find 연산의 시간복잡도가 거의 O(1)에 도달하는 이유를 설명하라.
